# 企画書｜IZA タスク管理の Notion 化

- 対象: IZAジャパン・高橋さん
- 構築支援: WonderPlace（Masashi）
- 作成日: 2026/06/13
- ステータス: 素案（レビュー待ち）

---

## 1. 背景

IZAジャパンは複数の事業を同時並行で運営しており、案件数・関係者・締切が増え続けている。

- **ワイン輸入（貿易）**: 約20〜30社のワイナリーと取引。輸入頻度はおおむね2か月に1回。ワイナリー折衝 → FedEx集荷申請 → インボイス確認 → 食品輸入届・通関入力 → 許可取得 → 倉庫出荷、という多段階の手続きが毎回発生する。
- **ワイン会運営**: 不定期開催。集客・参加者管理・入金・ワイン選定（在庫連動）・備品手配（グラス・紙皿等）・当日運営が付随する。
- **ワイン在庫管理**: 在庫本数の管理と発注判断（例: 残り10本で発注）。別途、在庫管理システム構築プロジェクトが進行中。
- **M&A案件**: LINE等での個別のやり取りが入口。個人的な関係性で進む案件が多く、属人的になりがち。
- **バックオフィス**: 経理、秘書採用、社内体制整備など。

現在はこれらを頭の中・LINE・メール・スプレッドシートのToDoに分散して管理しており、**全体像が一覧化されていない**。

## 2. 課題（2026/06/13 MTGで確認）

1. **案件過多で管理しきれない** — 何がどこまで進んでいるか把握できない。
2. **負のスパイラル** — 「緊急なことばかりに追われ、重要だが緊急でないことが全くできない」。
3. **属人化** — 高橋さんの頭の中にしかタスクがなく、人に振れない。だから秘書を採っても仕事を渡せない。
4. **ボールの所在が不明** — 自分待ち／相手待ち／外部（税理士・FedEx等）待ちが混在し、止まっている案件に気づけない。

## 3. 目的・ゴール

### 短期ゴール（Phase1）
- 全タスクを Notion 1か所に棚卸しし、**頭の中をゼロにする**。
- 事業ラベルとステータスで「全体が一覧で見える」状態をつくる。
- 週1〜2時間の定例レビューを**習慣化**する。

### 中期ゴール（Phase2〜）
- 案件・プロジェクト単位の**進捗管理**を可能にする。
- 「委任できるタスク」を可視化し、**秘書へ仕事を渡せる**状態にする。
- 繰り返し業務（輸入1回・ワイン会1回）を**テンプレ化**して再現可能にする。

### 最終ゴール
- **AIと人が連携できる組織体制の構築**。タスク管理の整備はその第一歩。
- 既存の議事録→アクションアイテム自動抽出（Claude / Cowork の運用）と接続し、会議で決まったことが自動でタスク化される流れをつくる。

## 4. なぜ Notion か

- **1枚のカードに集約**: タスク名・事業・期限・担当・優先度・関連書類・メモを1か所に。
- **同じデータを多角的に見られる**: カンバン／事業別／今週やること／カレンダー／担当別を、データを二重管理せずビューだけ切り替えて表示。
- **スモールスタート可能**: 無料プランで開始でき、課金が必要でも1人分で足りる構成。
- **拡張性**: 後からプロジェクトDB・自動化・AI連携を足せる。既に議事録DBが Notion で運用されており、連携しやすい。
- **委任しやすい**: 秘書ジョイン時にページ共有するだけで権限付与でき、担当・委任可否プロパティでそのまま渡せる。

## 5. 全体構想（アーキテクチャ）

```
🏠 IZA タスク管理（ホーム / ダッシュボード）
├─ 📖 使い方ガイド（運用マニュアルへのリンク）
├─ 📋 タスクDB ……★中心。複数ビューで運用
│    ├─ 🗂 カンバン（進行状況）
│    ├─ 🏢 事業別ボード
│    ├─ 📅 今週やること
│    ├─ 🎯 重要×緊急マトリクス
│    ├─ ⏰ 期限カレンダー
│    ├─ 👥 担当別
│    └─ ✅ 完了ログ
├─ 📁 プロジェクトDB（Phase2で追加）……案件単位の進捗管理
└─ 🗒 週次レビュー手順（チェックリスト）
```

- **Phase1 は「タスクDB1つ」だけで始める**（一度に全部やらない、というMTG方針に沿う）。
- 事業の分類は **5つの事業ラベル**（下表）。詳細プロパティとビュー設計は `02-database-design.md` を参照。

| ラベル | 対象 |
|---|---|
| 🍷 ワイン輸入 | 貿易・通関・輸入手続き |
| 🥂 ワイン会運営 | イベントの集客〜当日〜後処理 |
| 📦 ワイン在庫管理 | 在庫・発注・在庫システム |
| 🤝 M&A案件 | 案件ごとの進行管理 |
| 🏢 バックオフィス | 経理・採用・社内整備 |

### 課題への対応（設計の意図）

| 課題 | 設計での解決 |
|---|---|
| 管理しきれない | 全タスクを1つのDBに集約。事業ラベルで分割表示 |
| 重要×緊急の負のスパイラル | **優先度プロパティ（緊急×重要の4領域）**＋専用ビューで「重要だが緊急でない（第2領域）」を毎週必ず可視化 |
| 属人化・委任できない | **委任可否プロパティ**で渡せるタスクを見える化。テンプレ化で手順を標準化 |
| ボールの所在が不明 | **担当プロパティ**＋「確認待ち（相手ボール）」ステータスで停滞を検知 |

## 6. フェーズ計画

### Phase 0｜箱づくり（承認後すぐ・所要1〜2h）
- タスクDB・各ビュー・ホーム・マニュアルを Notion に構築。
- 高橋さんを招待しフルアクセス付与（MTGで実施済みのワークスペースを利用）。

### Phase 1｜棚卸し＆習慣化（〜2週間）
- 頭の中・LINE・メール・既存ToDo・議事録の宿題を**すべてタスク化**して入力。
- 各タスクに事業ラベル・優先度・期限・担当を付与。
- **週次レビューを開始**（まずは週2回でも可、慣れたら週1へ）。目的は「癖づけ」。

### Phase 2｜進捗管理＆委任（1〜2か月）
- プロジェクトDBを追加し、案件単位の進捗（%）とマイルストーンを管理。
- 繰り返し業務（輸入1回／ワイン会1回／M&A1件）を**テンプレート化**。
- 秘書ジョイン → 委任可否プロパティを使って委任フローを運用。

### Phase 3｜自動化・AI連携（その先）
- 議事録DB → アクションアイテム自動抽出 → タスクDBへ反映（Claude / Cowork）。
- 在庫管理システムとの連携（在庫が閾値を切ったら発注タスクを自動生成 等）。
- 定型業務のテンプレDB化・SOP（手順書）整備。

## 7. 運用ルール（要点）

- **週次レビュー（週1〜2h、強制的に時間を確保）**: 完了確認 → 新規棚卸し → ラベル付け → 「重要×緊急」で今週やる第2領域タスクを1〜3個選ぶ → 「今週やること」確定。
- **毎朝5分（任意）**: 「今週やること」ビューを開いて1日の段取り。
- **タスクは動詞で書く**（例: 「ワイン会用シートを作成する」）。「誰が・いつまでに・何を」を1枚に。
- 詳細手順は `03-manual.md` を参照。

## 8. 成功指標（KPI）

- 頭の中・LINEに散っていたタスクが Notion に**ゼロ化**して乗っている。
- 週次レビューが**4週連続**で回っている。
- **第2領域（重要だが緊急でない）タスクに毎週1つ以上着手**できている。
- 期限超過のまま放置されるタスクが減る。
- 秘書に委任できるタスクが一覧化され、実際に委任が始まっている（Phase2）。

## 9. リスク・留意点

- **入力が続かないリスク** → プロパティ必須項目を最小（タスク名・事業・ステータス）にし、週次レビューで強制的に棚卸しする運用でカバー。
- **作り込みすぎ** → Phase1は1DB＋ビューのみ。プロジェクトDBや自動化は後回し。
- **担当プロパティ** → 秘書ジョイン前は「人物」ではなく選択肢（高橋／秘書／Masashi／外部／未定）で運用し、後でメンバー型に切替可能。
- **無料プラン制限** → ブロック数等の制限に達したら有料化を検討（1人分課金で運用可能な構成）。
